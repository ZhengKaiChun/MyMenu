# 数据与权限

本文描述正式独立后台的数据结构。默认“本机体验”的数据单独存储在当前设备的geiwofan.preview.database.v1中，体验会话使用menu.preview前缀，不与正式账号混用。体验模式不向服务端写入，不支持跨设备同步；正式发布环境禁止使用它。

业务数据由独立服务端写入数据库，微信客户端只保存登录会话、当前小家和未发送菜篮。换手机登录后从服务端读取家庭、菜单、点餐与库存。

| 分类 | 表 | 归属与用途 |
| --- | --- | --- |
| 账号与身份 | users、identities、sessions | 每人独立账号，可绑定微信和手机号；会话可撤销 |
| 手机验证 | sms_challenges、sms_limits | 验证码HMAC、过期与尝试次数；不保存明文验证码 |
| 小家 | families、members | 每家独立成员、权限和身份称呼；身份称呼不代表管理权限 |
| 菜单 | collections、dishes | 家庭内可见的菜名、封面和介绍 |
| 私有做法 | recipes | 用料与步骤，仅所属小家的饲养员可读取 |
| 个人与家庭食材 | inventories | user_id或family_id二选一；导入生成独立家庭记录 |
| 家庭邀请 | invitations | 一次性随机邀请码、角色、有效期；服务端只存摘要 |
| 点餐 | orders、order_lines | 日期、餐次、来源、状态及当时的菜品快照 |
| 备菜勾选 | prep_checks | 同一小家同一天按食材名和单位合并，保留多个菜品来源 |
| 换菜 | changes | 申请人与原菜行关联，待回复时保留原菜单；同意后原子替换 |
| 菜谱分享 | shares、import_receipts | 选中菜品的独立快照、有效期、导入模式与回执 |
| 解散投票 | dissolutions、votes | 当前全体成员逐人表态，所有人同意才解散 |
| 通知 | notifications、subscription_grants | 站内消息独立保存，微信订阅需额外授权 |
| 文件 | media | 所有者、存储名与元信息；图片文件独立存放并签名访问 |
| 审计与幂等 | audit_logs、idempotency | 重要写入记录、重复提交防护，不记录密码或明文令牌 |
| 数据库版本 | schema_migrations | 迁移编号、内容校验值和执行时间 |

## 可见范围

饲养员可管理本小家的菜单、做法、食材、备菜与点菜回音。大懒猪可点菜、查看自己的回音与换菜、查看全家的每日菜单，接口不返回做法和用料。两种角色都可选择家庭身份、看历史与退出小家。创建者额外负责共同饲养员权限、转让与发起解散。

菜谱分享是明确选择后主动提供做法的功能。分享接收方只能导入自己拥有管理权限的小家；新建、追加、同名覆盖与整本替换均在服务端事务中完成，接收后的记录独立，之后修改不会影响来源。

## 保留与更新

三个自然月之前的餐次及关联记录定期清除；菜谱、库存与账号不会随餐次清除。本机数据库和图片不纳入Git，也不上传为源码成果。版本追溯覆盖代码与迁移，不复制用户私人业务数据。

菜品保存、目标菜谱覆盖和库存编辑带版本核验。重要家庭写入先锁定家庭并复核成员权限，避免同时操作产生部分成功；重发的点餐、复制与投票由幂等键保护。数量仅对同名同单位汇总，不自动换算。
